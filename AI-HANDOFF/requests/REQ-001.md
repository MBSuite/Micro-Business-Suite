# REQ-001: SSO login flow UI review and adjustment

- Status: ready-for-kiro
- Requester: OpenCode
- Owner: Kiro
- Screens/routes: `/login`, `/auth/sso-callback` (all 6 modules), Core `/login`
- Related files: module `app/login/page.tsx`, `app/auth/sso-callback/page.tsx`, Core `app/login/page.tsx`

## Goal / user need

Expose a working "Login with Core (SSO)" entry point on each module's login page and ensure the redirect flow lands the user back in the module app after Core authentication.

## Context and evidence

Backend (OpenCode-owned) is implemented and deployed:
- Core: `GET /api/auth/jwks` (RS256 public key), `POST /api/auth/sso-token` (audience param, 5min token).
- Modules: `POST /api/auth/sso` (verifies SSO token, creates/finds user by `core_user_id`, sets session cookie).
- Module login page now has a "Login with Core (SSO)" button redirecting to:
  `https://micro-business-suite.vercel.app/login?redirect=<module>/auth/sso-callback&audience=mbs-<module>`
- Core login page reads `redirect` + `audience`, after successful login fetches `/api/auth/sso-token`, then redirects to `<redirect>?sso_token=...`.
- Module callback page reads `sso_token`, POSTs to `/api/auth/sso`, then redirects to `/`.
- Registration link points to Core `/register`.

## Requested outcome

Kiro to review and adjust the UI/UX of the SSO login flow:
1. Button styling/positioning consistent with each module's design system.
2. Loading/error/success states for the SSO redirect (currently minimal).
3. Callback page UX (loading spinner, error display, retry).
4. Standalone mode: when `MBS_HUB_URL` is not set, the SSO button should be hidden.
5. Accessibility (keyboard, screen reader) for the new button and link.

## Acceptance criteria
- [ ] SSO button visible and usable on each module login page when `MBS_HUB_URL` is set.
- [ ] Full flow: module → Core login → module callback → module home, with session cookie set.
- [ ] Error states displayed clearly (invalid token, network failure).
- [ ] No regression to existing local (email/password) login.

## Owner plan / questions

Kiro: please review the inserted button and callback page. OpenCode can adjust backend if UI needs different contract (e.g., token delivery via postMessage instead of query param).

## Handoff result
- Changed files: module `app/login/page.tsx`, `app/auth/sso-callback/page.tsx`, Core `app/login/page.tsx`, `lib/auth/sso.ts`, `app/api/auth/sso/route.ts`, `app/api/auth/jwks/route.ts`, `app/api/auth/sso-token/route.ts`
- Backend contract: `POST /api/auth/sso` body `{ token }` → `{ user }` + session cookie; `POST /api/auth/sso-token` body `{ audience }` → `{ token, jti }` (requires Core session cookie).
