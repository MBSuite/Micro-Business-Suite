# REQ-005: SSO login flow UI review — micro-business-pharmacy

- Status: ready-for-kiro
- Requester: OpenCode
- Owner: Kiro
- Screens/routes: `/login`, `/auth/sso-callback`
- Related project: micro-business-pharmacy (https://micro-business-pharmacy.vercel.app)
- Related files: `app/login/page.tsx`, `app/auth/sso-callback/page.tsx`

## Goal / user need

Review and polish the SSO login UI for micro-business-pharmacy so users can sign in via Core (SSO) and return to the module app.

## Context and evidence

Backend (OpenCode) is implemented and deployed:
- Core: `GET /api/auth/jwks`, `POST /api/auth/sso-token` (audience `mbs-pharmacy`).
- Module: `POST /api/auth/sso` (verifies SSO token, creates/finds user by `core_user_id`, sets session cookie).
- Current login page has a "Login with Core (SSO)" button redirecting to:
  `https://micro-business-suite.vercel.app/login?redirect=https://micro-business-pharmacy.vercel.app/auth/sso-callback&audience=mbs-pharmacy`
- Callback page receives `?sso_token=...`, POSTs to `/api/auth/sso`, then redirects to `/`.

## Requested outcome

Kiro to review and adjust UI/UX for this module:
1. Button styling/positioning consistent with this module's design system.
2. Loading/error/success states for the SSO redirect.
3. Callback page UX (spinner, error display, retry link).
4. Standalone mode: hide SSO button when `MBS_HUB_URL` is not set.
5. Accessibility (keyboard, screen reader).

## Acceptance criteria
- [ ] SSO button visible and usable on login page.
- [ ] Full flow works: module → Core login → callback → module home, session cookie set.
- [ ] Error states displayed clearly.
- [ ] No regression to existing local (email/password) login.

## Handoff result (OpenCode)
- Changed files: `app/login/page.tsx`, `app/auth/sso-callback/page.tsx`, `lib/auth/sso.ts`, `app/api/auth/sso/route.ts`
- Backend contract: `POST /api/auth/sso` body `{ token }` → `{ user }` + session cookie.
- Verification: typecheck passes; Core JWKS returns 200.
